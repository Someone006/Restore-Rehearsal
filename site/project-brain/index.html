Project Brain

One private evidence graph for the whole project.

Statically scan a Git repository or any ordinary local project folder into one focused .rrbrain SQLite file—without executing the project’s code.

Build a local brain Read the technical guide
Local and inspectable
  • Git: optional
  • Storage: one private SQLite file

  • Visual: self-contained offline HTML
  • Execution: bounded static scan only

Connected evidence

More than a pile of notes.

Project Brain records where evidence came from and how project elements connect, so a person or agent can ask a focused question instead of ingesting the entire tree.

Architecture and dependencies

Source areas, manifests, configuration, APIs, infrastructure, deployment files, dependency edges, and recovery signals.

Tests and review findings

Local test evidence plus bounded imports such as SARIF, JUnit, coverage, OpenAPI, SBOM, Terraform, and Compose fragments.

Memory with provenance

Decisions, failed attempts, active findings, recovery knowledge, snapshots, diffs, and change-impact traversal.

First local snapshot

Build, query, and visualize.

The scan is bounded and static. The generated visualization is a self-contained local HTML file with no remote scripts, fonts, analytics, or requests.

rehearse brain build . --output project.rrbrain --label initial
rehearse brain summary project.rrbrain --json
rehearse brain query project.rrbrain "database recovery" --json
rehearse brain visualize project.rrbrain --output project-brain.html

Privacy boundary

Local does not mean automatically share-safe.

A brain can contain sensitive project metadata. Keep *.rrbrain out of version control and review ignore rules before scanning. .rehearseignore controls what the scanner reads; it is not a Git privacy boundary.

Evidence, not authority

Focused context with human review.

Findings point to missing or conflicting evidence and provide a verification route. They are not automatic legal, privacy, accessibility, security, or architecture conclusions.
